# M Pharmacy POS

نظام إدارة صيدلية بواجهة عربية RTL ونقطة بيع سريعة. الإصدار الحالي تطبيق React/TypeScript وExpress على Node.js، ويستخدم Drizzle ORM وقاعدة MySQL متوافقة ومدارة. هذا هو إصدار Manus المستضاف؛ ملفات PHP/XAMPP القديمة ليست نقطة التشغيل لهذا المشروع.

## الوظائف والأدوار

تتضمن مساحة العمل نقطة البيع، الكتالوج والباركود، الخدمات السريعة، الفواتير والإيصالات الحرارية، إدارة المخزون والصلاحية، الورديات وتسوية الصندوق، لوحة المؤشرات، التقارير، المستخدمين وسجل التدقيق. تُحفظ العمليات المالية والمخزون في قاعدة البيانات. لا يستورد التطبيق بيانات تجريبية أو ملفات قاعدة PHP تلقائيًا.

للمدير صلاحيات لوحة المؤشرات والتقارير وإدارة المستخدمين والأسعار ومراجعة الورديات والتصدير. يستطيع الصيدلي البيع وإدارة ورديته النشطة وعرض المخزون، ولا يحصل عبر API على سعر الشراء أو تنزيلات المدير. تُفرض هذه الصلاحيات في الخادم؛ إخفاء زر من الواجهة ليس حدًا أمنيًا.

## متطلبات التشغيل

- Node.js 22.x؛ صورة الإنتاج مبنية على `node:22-bookworm-slim`.
- pnpm بالإصدار المثبت في المشروع `10.18.0`، وCorepack لتفعيله.
- قاعدة MySQL متوافقة يمكن الوصول إليها عبر `DATABASE_URL`. في Manus تُستخدم قاعدة المشروع المدارة. للتطوير الذاتي استخدم قاعدة محلية منفصلة. يتصل التطبيق كذلك بـ TiDB Serverless في بيئة Manus.
- Git مطلوب لجلب المصدر أو تحديثه. Docker اختياري للتشغيل الذاتي بالحاوية.

لا يحتاج النظام إلى XAMPP أو Apache أو PHP في مسار Manus الحالي. قاعدة البيانات هي مكان التخزين الدائم؛ لا تعتمد الفواتير أو المخزون أو الجلسات على ملفات الحاوية.

## إعداد محلي من الصفر

### 1. تثبيت الأدوات وتهيئة قاعدة بيانات محلية

ثبّت Node.js 22 وفعّل نسخة pnpm المثبتة في المشروع:

```bash
corepack enable
corepack prepare pnpm@10.18.0 --activate
node --version
pnpm --version
```

أنشئ قاعدة محلية ومستخدمًا مخصصًا لها في MySQL. استبدل النصوص بين `<...>` بقيم محلية قوية؛ لا تستخدم حساب root للتطبيق ولا تنسخ كلمة المرور إلى Git أو المحادثات:

```sql
CREATE DATABASE pharmacy_pos_db
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'mpharmacy_app'@'localhost' IDENTIFIED BY '<كلمة-مرور-محلية-قوية>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES
  ON pharmacy_pos_db.* TO 'mpharmacy_app'@'localhost';
```

ينبغي أن يملك مستخدم الترحيلات الصلاحيات اللازمة على مخطط هذه القاعدة فقط. لا تمنحه صلاحيات عامة على بقية قواعد MySQL. عند الاتصال بخدمة بعيدة، اتبع إعداد TLS الذي توفره الخدمة.

### 2. إعداد متغيرات البيئة

من جذر المشروع أنشئ ملف `.env` محليًا، ولا ترفعه إلى Git. صيغة القيم المطلوبة:

```dotenv
PORT=3000
DATABASE_URL=mysql://mpharmacy_app:<كلمة-المرور-المشفرة-للعنوان>@127.0.0.1:3306/pharmacy_pos_db
PHARMACY_INITIAL_ADMIN_PASSWORD=<سر-محلي-مؤقت-بطول-12-محرفًا-على-الأقل>
```

`DATABASE_URL` سرّ، حتى لو كان الملف محليًا. إذا احتوت كلمة مرور قاعدة البيانات على محارف خاصة بعناوين URL، فشفّرها قبل وضعها داخل الرابط. لا تستخدم مثالًا حرفيًا أو كلمة مرور افتراضية. اترك `PORT` على 3000 للتشغيل المحلي المعتاد.

`PHARMACY_INITIAL_ADMIN_PASSWORD` مطلوب فقط عندما تكون قاعدة الصيدلية جديدة ولا تحتوي مستخدمًا. يجب أن يبلغ طوله 12 محرفًا على الأقل. ينشئ التطبيق الحساب `admin` مرة واحدة، ويحفظ بصمة `scrypt` لا كلمة المرور نفسها. بعد إنشاء المدير، احذف هذا المتغير من `.env` والبيئة التي شغّلت التطبيق. لا يتيح النظام إنشاء حساب مدير عبر تسجيل عام.

### 3. تثبيت المشروع وتشغيل الترحيلات

```bash
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm check
pnpm test
pnpm dev
```

يقرأ `pnpm dev` ملف `.env`، ويتطلب اتصال قاعدة البيانات. ستعمل واجهة التطوير على المنفذ 3000 ما لم تغيّر `PORT`. بعد بدء الخادم افتح التطبيق المحلي وسجّل الدخول باسم `admin` وكلمة المرور التي وضعتها في متغير التهيئة، ثم احذف ذلك المتغير.

اختبارات `pnpm test` هي اختبارات نطاق للمال والتاريخ والخدمات، ولا تنفذ معاملات بيع أو تعدل بيانات قاعدة Manus. لا تختبر على قاعدة بيانات الإنتاج أو المعاينة المشتركة.

## الأوامر وسير العمل

| الأمر | الاستخدام |
| --- | --- |
| `pnpm dev` | خادم Express وVite للتطوير؛ يحتاج قاعدة بيانات ومديرًا مهيأً |
| `pnpm check` | فحص TypeScript من دون إصدار ملفات |
| `pnpm test` | تشغيل اختبارات Vitest |
| `pnpm build` | بناء ملفات الواجهة والخادم داخل `dist/` |
| `pnpm start` | تشغيل ترحيلات Drizzle المسجلة ثم بدء خادم الإنتاج |
| `pnpm db:migrate` | تطبيق ملفات الترحيل المسجلة يدويًا على `DATABASE_URL` المحدد |
| `pnpm exec drizzle-kit generate` | إنشاء ملف ترحيل جديد بعد تعديل `drizzle/schema.ts` ومراجعة الناتج |

عند تغيير المخطط، أنشئ ترحيلًا جديدًا وراجع SQL قبل تطبيقه. اختبر تغييرات المخطط على قاعدة محلية منفصلة أولًا. لا تستخدم `db:push` أو أوامر حذف/إعادة ضبط على قاعدة تحتوي بيانات العمل. في Manus تتشارك بيئة التطوير والنشر قاعدة المشروع؛ أي ترحيل أو كتابة عليها يؤثر في البيانات نفسها.

## إعداد Manus والنشر

هذا المشروع مهيأ في Manus WebDev بخادم وقاعدة بيانات مُدارة. يحتفظ `Dockerfile` بنسخة Node وpnpm، ويبني الواجهة، ثم يشغّل `pnpm start`. يطبّق أمر البداية ملفات Drizzle المسجلة ويستمع على `PORT`؛ مسار الصحة هو `/api/health`. يحصل مشروع Manus على `DATABASE_URL` من إعداد قاعدة البيانات المدارة، فلا تضف نسخة محلية من السر إلى ملفات المشروع.

لتهيئة مشروع جديد مماثل، فعّل قدرات الخادم وقاعدة البيانات، اربط قاعدة MySQL المدارة، وتحقق من إعداد Docker ونقطة الصحة قبل النشر. مرّر كلمة مرور المدير الأولى عبر وسيلة الأسرار المحمية فقط، قبل إنشاء الحساب الأول؛ اسحبها بعد تهيئة المدير. لا تضفها إلى `.env.example` بقيمة حقيقية أو إلى إعدادات الواجهة.

عاين التطبيق وسجّل الدخول واختبر الإعداد قبل الإطلاق. معاينة Manus ليست نشرًا عامًا، والنشر التلقائي غير مفعّل في هذا المشروع. يتطلب جعل الموقع عامًا موافقة المالك. حفظ قاعدة البيانات دائم، لكن خدمة Autoscale قد تدخل السكون ثم تستيقظ عند الطلب؛ لا يُضمن تشغيل خادم ساخن 24/7.

للتشغيل الذاتي داخل Docker، جهّز قاعدة MySQL خارج الحاوية وملف متغيرات محليًا غير مرفوع إلى Git، ثم:

```bash
docker build -t m-pharmacy .
docker run --rm --name m-pharmacy \
  --env-file .env -p 3000:3000 m-pharmacy
```

يجب أن تشير `DATABASE_URL` إلى قاعدة يمكن للحاوية الوصول إليها؛ `127.0.0.1` داخل الحاوية يشير إلى الحاوية نفسها. لا تضع قاعدة بيانات دائمة داخل نظام ملفات الحاوية. في الاستضافة الذاتية، اضبط TLS وجدار الشبكة ونسخ قاعدة البيانات وفق مزود MySQL، واحذف متغير المدير الأول من بيئة التشغيل بعد إنشاء الحساب.

## المصادقة وحماية API وقاعدة البيانات

تستخدم الجلسات رموزًا عشوائية ويُخزن تجزؤ رمز الجلسة في MySQL. كلمات المرور محفوظة ببصمة scrypt. ملفات تعريف الارتباط `HttpOnly` و`Secure` و`SameSite=None` لتوافق معاينة HTTPS المضمنة. تحمل طلبات التغيير رمز CSRF، وتتحقق مسارات الإدارة من الدور على الخادم. تُرسل بيانات API الحساسة دون تخزين مؤقت؛ ويحد Express حجم JSON إلى 1 MiB والنماذج المشفرة إلى 64 KiB.

في مراجعة المصدر بتاريخ 2026-10-28 لم يظهر SQL Injection مؤكد: استعلامات التطبيق مبنية بـ Drizzle، وقيم المرشحات تُمرر عبر أدوات الربط. الاستخدامات الصريحة لـ`sql` تشير إلى أعمدة ثابتة أو قيم ممررة، وأسماء جداول النسخة الاحتياطية قائمة ثابتة، بينما تُهرّب قيم الصفوف النصية عند إنشاء SQL. تحقق API من مدخلات النماذج عبر Zod ومن الأموال والتواريخ في الخادم، ولا يعتمد على تحقق المتصفح وحده. تتضمن قاعدة البيانات مفاتيح أساسية وأجنبية وفهارس فريدة وأنواعًا محددة للأدوار والدفع وحالة الوردية. أُجري فحص قراءة فقط للقيم المالية والكميات الحالية، ولم تظهر سجلات سالبة ضمن الحقول المفحوصة. هذا الفحص لا يثبت وجود قيد `CHECK` دائم على قاعدة البيانات.

حدد التدقيق ثلاث نقاط يجب علاجها برمجيًا قبل اعتبار المراجعة الأمنية مكتملة: تصدير CSV يحيط القيم بعلامات اقتباس لكنه لا يحيّد بادئات صيغ جداول البيانات مثل `=`, `+`, `-`, و`@`؛ تقرير المدير يقبل نطاق تواريخ غير محدود ويحمل جميع الفواتير وبنودها للذاكرة؛ ومدقق معرّف المسار يقبل أي قيمة تتحول إلى عدد صحيح موجب، من دون حصرها بصيغة عشرية وحد `INT` في MySQL. أوصى التدقيق بتحييد خلايا CSV، ووضع حد أقصى للفترة أو التجميع/الصفحات في قاعدة البيانات، والتحقق من المعرّفات ضمن مجال `INT`.

هذه النسخة توثّق نتائج التدقيق ولا تطبق إصلاحات API أو تعديلات مخطط قاعدة البيانات. لذلك لا تعتبر النقاط الثلاث أعلاه محلولة. كما لا توجد حاليًا طبقة تحديد معدل محاولات الدخول على مستوى التطبيق؛ فعّل حماية مناسبة على بوابة الاستضافة عند النشر العام، أو أضف محددًا مركزيًا قبل فتح التسجيل للجمهور. تجنب كشف تفاصيل SQL أو أسرار الاتصال في سجلات الدعم.

## مسارات API الرئيسية

جميع المسارات أدناه تحت البادئة `/api`، وتتطلب جلسة صالحة ما لم يذكر خلاف ذلك. `GET /auth/status` متاح قبل تسجيل الدخول لإظهار حالة المصادقة وتهيئة النظام، و`POST /auth/login` يستخدم رمز ما قبل المصادقة. مسارات الكتابة تتطلب رمز CSRF.

| المسارات | الصلاحية والاستخدام |
| --- | --- |
| `/auth/status`, `/auth/login` | فحص الحالة وتسجيل الدخول |
| `/auth/me`, `/auth/logout`, `/auth/change-password` | بيانات الجلسة وإدارتها؛ تتطلب جلسة |
| `/pos`, `/checkout`, `/invoices/:id` | كتالوج نقطة البيع، إنشاء فاتورة، واسترجاع فاتورة وفق صلاحية صاحبها أو المدير |
| `/medicines` | عرض المخزون للمستخدمين المسجلين؛ الإضافة والتعديل والتعطيل للمدير |
| `/medicines/export.csv`, `/dashboard`, `/reports`, `/users`, `/audit` | وظائف المدير |
| `/shifts`, `/shifts/:id`, `/shifts/:id/close` | وردية المستخدم؛ يعرض سجل الورديات الكامل للمدير فقط |
| `/backups/shifts/:id.sql.gz` | تنزيل نسخة SQL كاملة للمدير بعد إغلاق وردية |
| `/health` | فحص صحة الخدمة من دون تفاصيل الحسابات |

## النسخ الاحتياطية والاستعادة

بعد إغلاق الوردية، يستطيع المدير تنزيل ملف `m-pharmacy-backup-shift-<id>.sql.gz`. رغم ارتباط زر التنزيل بإغلاق وردية محددة، يحتوي الملف على تصدير كامل للجداول المدرجة في التطبيق، وليس نسخة تخص الوردية وحدها. يُجهز الملف للتنزيل ولا يُحفظ بوصفه ملفًا دائمًا في الحاوية؛ خزّنه في مكان احتياطي آمن خارج التطبيق.

يتضمن التصدير بيانات الحسابات وبصمات كلمات المرور وسجلات الصيدلية، لذلك يُعامل كبيانات حساسة. لا يصدّر صفوف جلسات الدخول الفعالة. الاستعادة تكون إلى قاعدة فارغة مخصصة، ولا تستبدل بيانات قاعدة تشغيل قائمة:

```bash
gunzip -c m-pharmacy-backup-shift-<id>.sql.gz | mysql \
  --host=<مضيف-قاعدة-البيانات> \
  --user=<مستخدم-الاستعادة> \
  --password \
  pharmacy_pos_db
```

سيطلب عميل MySQL كلمة المرور تفاعليًا. قبل الاستعادة تحقق من مصدر الملف، واحتفظ بنسخة مستقلة من أي قاعدة قد تتأثر، ولا تشارك الملف أو تضعه في مستودع عام. اختبر استعادة النسخة في قاعدة منفصلة قبل الاعتماد عليها.

## استكشاف الأخطاء

- **قاعدة البيانات غير متاحة أو `DATABASE_URL` مطلوب:** تأكد أن MySQL يعمل، وأن الرابط صحيح ومشفّر بحسب صيغة URL، وأن الحساب يملك صلاحيات قاعدة `pharmacy_pos_db` المحددة.
- **لا تظهر صفحة تسجيل الدخول أو يتوقف الخادم عند الإقلاع:** تأكد من نجاح `pnpm db:migrate` ومن وصول التطبيق إلى قاعدة البيانات. عند أول تشغيل، أضف `PHARMACY_INITIAL_ADMIN_PASSWORD` محليًا بطول 12 محرفًا على الأقل ثم أعد التشغيل.
- **بعد حذف سر المدير لا تستطيع إنشاء الحساب الأول:** سر التهيئة مطلوب قبل إنشاء أي مستخدم؛ لا يوجد مسار تسجيل عام. أعد ضبط متغير السر عبر قناة آمنة وشغّل التهيئة عند الحاجة فقط، ثم أزله بعد نجاح الإنشاء.
- **خطأ ترحيل:** راجع أولًا اسم القاعدة وحالة جدول `__drizzle_migrations`. لا تحذف بيانات أو جداول يدويًا ولا تعاود ترحيلًا عشوائيًا على قاعدة العمل.
- **حالة دخول قديمة أو رمز CSRF منتهي:** سجّل الخروج وأعد تحميل الصفحة ثم سجّل الدخول من جديد. الجلسة العادية 12 ساعة، و«تذكرني» 30 يومًا.
- **تعذر تنزيل النسخة بعد إغلاق الوردية:** إغلاق الوردية يُحفظ أولًا. يستطيع المدير إعادة التنزيل من سجل الورديات المغلقة؛ فشل التنزيل لا يعيد فتح الوردية.

لأي تغيير على المصادقة أو الصلاحيات أو بيانات حقيقية، راجع الأثر على قاعدة Manus المشتركة قبل تنفيذه. لا تضع ملفات `.env` أو النسخ المضغوطة في Git.
